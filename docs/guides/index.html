What’s new in 3.1.0

3.1.0 is the first release of the 3.x line, and includes everything from the 3.0.0-alpha.1 and 3.0.0-alpha.2 prereleases. Every built-in view is now a descriptor with one shared modifier table, the same views render to HTML on a server, and the framework behaves closer to SwiftUI in gestures, transitions, presentations and accessibility.

Try any of it in the Playground: every runnable sample in these guides has an Open in Playground button.

Static rendering for SEOswiftui-for-web/server: renderToString, renderDocument, DocumentMetadata, sitemap. Islands and hydrationmount(host, { mode: 'replace' | 'adopt' }) and whenVisible. Presentations.sheet, .alert, .confirmationDialog, .fullScreenCover and dismiss. Gestures and animation.simultaneousGesture, .highPriorityGesture, removal transitions, matchedGeometryEffect. Reactivity and layoutReactive ForEach, Show, ordered modifiers, frame(alignment:), lazy stacks. AccessibilityNative controls and WAI-ARIA patterns with keyboard support. Release buildnode scripts/build.js with --bundle, --hash, --no-minify. Migrating from 3.0Removed *View classes and extend* helpers, /performance, Chart changes.

Highlights

  • One view model. Text, the stacks, the controls, List, NavigationStack, the shapes and Chart are all immutable descriptors. Every modifier returns a new descriptor, and every view has the whole modifier table. The *View classes are gone (migration).
  • Static rendering. The new swiftui-for-web/server entry renders views to HTML in Node with the framework’s own renderers, and writes document metadata, JSON-LD and sitemaps.
  • Hydration. mount(host, { mode: 'adopt' }) renders onto the server’s DOM nodes, keeping their identity, focus and scroll offsets.
  • Presentations on one controller. Sheets, full-screen covers, alerts and confirmation dialogs all use <dialog>.showModal(), trap focus, return it, and put dismiss in the environment.
  • Gestures and transitions. Gesture composition with GestureMask, and .transition now animates removal from Show, ForEach and a navigation pop.
  • Reactivity. ForEach is reactive and keyed when given a State, a Binding or a function; Text(state) and style modifiers accept a State; development builds warn about the Text(count.value) mistake.
  • Release build. --bundle scope-hoists an app into one module, --hash names files by content, and npm run size keeps the library under a 120 KB gzip budget.
  • Reliable cold loads. serve.py no longer resets connections on a cold load and reports a module that fails to load instead of showing a blank page.

A first taste

This counter uses the 3.1 reactivity rules: pass the State itself, or a function for derived text.

import { App, VStack, Text, Button, State, Font } from 'swiftui-for-web';

const count = new State(0);

App(() =>
  VStack({ spacing: 12 },
    Text(count).font(Font.largeTitle),
    Text(() => (count.value === 1 ? '1 tap' : `${count.value} taps`)),
    Button('Tap', () => { count.value += 1; })
  ).padding(24)
).mount('#root');
