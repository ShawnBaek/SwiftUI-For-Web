Release build

Development needs no build step. node scripts/build.js makes an optional, smaller release with Node built-ins only, and its output behaves exactly like the unbuilt source.

Build an app

# Tree-shaken and minified, into dist/hello-world
node scripts/build.js --entry Examples/HelloWorld/index.html --out-dir dist/hello-world

# One scope-hoisted module, content-hashed file names
node scripts/build.js --entry Examples/HelloWorld/index.html --out-dir dist/hello-world --bundle --hash

# Readable output (still tree-shaken)
node scripts/build.js --entry Examples/HelloWorld/index.html --out-dir dist/hello-world --no-minify

# The whole library, into dist/
node scripts/build.js
OptionEffect
--entry <file>Build one application from its HTML entry. The builder follows static HTML, JavaScript and CSS references, routes named framework imports to their defining modules, and drops unreachable modules.
--out-dir <dir>Output directory (default dist). Inside the repository it must be dist or a directory in it.
--configuration releaseThe production configuration (the only one).
--no-minifyKeep the output readable.
--hashName every emitted file name.<hash>.ext, rewrite the references, and write manifest.json mapping source paths to hashed ones. A file’s hash covers everything it reaches.
--bundleScope-hoist the page’s module scripts and their static imports into one ES module, bundle.js (bundle.<hash>.js with --hash), and point index.html at it. Modules reached only through import('…') become chunk-*.js files.

What the release contains

  • <link rel="modulepreload"> for every module the page imports statically, so they download in parallel.
  • build-report.json: retained and removed files, external references, raw and gzip totals, and with --bundle the bundled modules and chunks.
  • Development checks compiled out: DEV_BUILD is rewritten to false, so the untracked-read warning and the “created at” sites in render errors cost nothing in production.

How --bundle works

The bundler parses each module, resolves its scopes, and concatenates the modules in ES module evaluation order. A top-level name is renamed only where it would collide, and only the references that resolve to it change, so live bindings, hoisting, temporal dead zones, cycles, namespace imports (frozen objects with getters) and class and function names behave as they do between modules. import.meta.url keeps pointing at each module’s original location. The output is byte-for-byte deterministic.

Top-level await and eval are rejected. Stack traces, and the development warnings that read them, point into the bundle. A dynamic chunk’s dependencies run before its own modules rather than interleaved with them.

Size budget and validation

npm run size       # fails when the gzipped dist/ total passes 120 KB
npm run validate   # npm test, browser tests, the build and the size report

Serving the unbuilt source in production? Use a host that accepts many connections (HTTP/2), or the --bundle build: a cold load of the source opens dozens of module requests at once.
