Reactivity and layout

A view body runs once, at mount. State changes re-run only the small effects bound to the DOM nodes that read them. These are the rules, and the layout behaviour that changed in 3.1.

Reactive reads

  • Pass a State or Binding itself: Text(count), .opacity(isVisible), .foregroundColor(color), .padding(spacing), .background(…), .font(…), .frame(…), .cornerRadius(…), .shadow(…) and the accessibility modifiers update on their own.
  • Use a function for derived values: Text(() => `${count.value} items`).
  • Text(count.value) is a snapshot: it renders once and never updates.

The development warning for untracked reads

Reading State.value while building a view, outside any reactive scope, logs a warning once per call site, naming the line. It is on in the source tree and compiled out of the release build. Run this and look at the console:

import { App, VStack, Text, Button, State } from 'swiftui-for-web';

const count = new State(0);

App(() =>
  VStack({ spacing: 8 },
    Text(count.value),              // warns: a snapshot that never updates
    Text(count),                    // updates
    Text(() => `Double: ${count.value * 2}`), // updates
    Button('Add', () => { count.value += 1; })
  ).padding(24)
).mount('#root');

Show

Show(when, then, otherwise) is the reactive if. The when function is tracked; switching branches mounts one and disposes the other, with its effects.

import { App, VStack, Text, Toggle, Show, State, Color } from 'swiftui-for-web';

const signedIn = new State(false);

App(() =>
  VStack({ spacing: 12 },
    Toggle('Signed in', signedIn.binding),
    Show(() => signedIn.value,
      Text('Welcome back!').foregroundColor(Color.green),
      Text('Please sign in.').foregroundColor(Color.secondary)
    )
  ).padding(24)
).mount('#root');

Reactive, keyed ForEach

Given a State, a Binding or a function, ForEach is reactive and keyed. Rows whose key stays keep their DOM and effects, new keys mount, removed keys are disposed. A new object with the same key (an immutable update with map) remounts its row so its closures see the new item. The key is the id option (a property name or a function), else the item’s id, else its index. A plain array is a static snapshot. Rows of a reactive ForEach inside a List are list rows, including rows added later. For(each, render, key) is the same thing under its old name, deprecated.

import { App, VStack, HStack, Text, Button, ForEach, State, Color } from 'swiftui-for-web';

const people = new State([
  { id: 'a', name: 'Ada', score: 3 },
  { id: 'b', name: 'Grace', score: 5 },
]);

const bump = (id) => {
  people.value = people.value.map((p) => (p.id === id ? { ...p, score: p.score + 1 } : p));
};

App(() =>
  VStack({ alignment: 'leading', spacing: 8 },
    ForEach(people, { id: 'id' }, (person) =>
      HStack({ spacing: 12 },
        Text(`${person.name}: ${person.score}`),
        Button('+1', () => bump(person.id))
      )
    ),
    // Derived and sorted: a function.
    Text('Leader:').foregroundColor(Color.secondary),
    ForEach(() => [...people.value].sort((a, b) => b.score - a.score).slice(0, 1), { id: 'id' },
      (person) => Text(person.name))
  ).padding(24)
).mount('#root');

Ordered modifiers

Modifier order has SwiftUI’s meaning. Padding, background, frame, border, clipping, opacity, shadow and mask start a new layer when an earlier modifier on the view would change their meaning, so padding after a background goes outside it.

import { App, HStack, Text, Color } from 'swiftui-for-web';

App(() =>
  HStack({ spacing: 24 },
    Text('Inner then outer')
      .padding(8).background(Color.yellow)
      .padding(8).background(Color.orange),
    Text('Rounded, then bordered')
      .padding(12).background(Color.mint).cornerRadius(12)
      .padding(4).border(Color.gray, 1)
  ).padding(24)
).mount('#root');

frame(alignment:)

.frame({ width, height, alignment }) positions the content inside the frame: topLeading, top, topTrailing, leading, center, trailing, bottomLeading, bottom, bottomTrailing. maxWidth: Infinity fills along a stack’s axis, sharing space with spacers, and frames use box-sizing: border-box.

import { App, VStack, Text, Color } from 'swiftui-for-web';

App(() =>
  VStack({ spacing: 12 },
    Text('bottomTrailing')
      .frame({ width: 220, height: 90, alignment: 'bottomTrailing' })
      .background(Color.secondarySystemBackground),
    Text('Fills the width')
      .padding(8)
      .frame({ maxWidth: Infinity, alignment: 'leading' })
      .background(Color.yellow)
  ).padding(24)
).mount('#root');

Lazy stacks

LazyVStack and LazyHStack render a row when it comes near the viewport (or the nearest scrolling ancestor) and keep it once rendered, as in SwiftUI. Until then each row is a placeholder of an estimated size. Without IntersectionObserver, and in a static render, every row renders.

import { App, ScrollView, LazyVStack, ForEach, Text } from 'swiftui-for-web';

const rows = Array.from({ length: 1000 }, (_, i) => ({ id: i }));

App(() =>
  ScrollView(
    LazyVStack({ spacing: 4 },
      ForEach(rows, { id: 'id' }, (row) => Text(`Row ${row.id}`).padding(6))
    )
  ).frame({ height: 300 })
).mount('#root');

// Scroll the list, then look again: more rows render as they come near.
setTimeout(() => {
  const rendered = document.querySelectorAll('#root [data-view="Text"]').length;
  console.log(`Rendered ${rendered} of ${rows.length} rows`);
}, 500);

navigationTitle

.navigationTitle(title) sets the document title while its view is shown and restores the previous one when the view goes away (a popped screen, a closed branch). A State or Binding title stays in sync, and renderDocument uses it when the metadata has no title.

import { App, VStack, Text, TextField, State } from 'swiftui-for-web';

const title = new State('Inbox');

App(() =>
  VStack({ spacing: 8 },
    TextField('Title', title.binding),
    Text(() => `document.title follows: ${title.value}`)
  )
    .padding(24)
    .navigationTitle(title)
).mount('#root');
