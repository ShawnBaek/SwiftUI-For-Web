Islands and hydration

Keep a page server-rendered and activate SwiftUI for Web only where it is interactive, without a layout shift, and without throwing away the server’s DOM.

Mount modes

CallWhat happens to the host’s markup
App(view).mount(host)Cleared, then the view renders into the host.
App(view).mount(host, { mode: 'replace' })Kept as a static fallback until the view has rendered off-document; then the two swap in one step (replaceChildren), and the host keeps its height until the next frame, so there is no layout shift.
App(view).mount(host, { mode: 'adopt' })Hydrated: the view renders onto the server’s nodes instead of new ones.
app.unmount()Releases the app’s handlers, effects, tasks and lifecycle callbacks.

host is a selector or an element.

Hydrating server markup with adopt

With mode: 'adopt', element creation during the client’s first render claims the matching element from the server markup (renderToString or renderDocument), so effects, delegated handlers, gestures, lifecycle callbacks and the element references their closures capture all belong to the server’s nodes.

  • Each element keeps its identity, focus (with a text field’s selection) and scroll offset.
  • A claimed element is emptied and rebuilt by its renderer, so the result is always the client’s tree. Where the markup differs (another tag, or outside the enclosing view’s element) the element is created fresh, and development builds warn at the first difference.
  • Text typed, or a box ticked, in a server-rendered field before hydration is kept when its binding still holds the server’s value, and passed to the binding; otherwise the binding’s value replaces it.
  • Comments and whitespace in the markup don’t matter. Adopting a host that already has a mounted app unmounts that app first (development builds warn).

This sample puts the markup renderToString produces for the counter into #root, as a server would, then adopts it:

import { App, VStack, Text, Button, State } from 'swiftui-for-web';

const count = new State(0);
const Counter = () =>
  VStack({ spacing: 8 },
    Text(count),
    Button('Add one', () => { count.value += 1; })
  );

// What renderToString(Counter()) returns, as the server sent it.
document.getElementById('root').innerHTML =
  '<div data-view="VStack" style="display: flex; flex-direction: column; align-items: center; gap: 8px;"><span data-view="Text">0</span><button data-view="Button" style="cursor: pointer; border: none; background: transparent; padding: 0; font: inherit; color: rgba(0, 122, 255, 1);">Add one</button></div>';

const serverButton = document.querySelector('#root button');
App(Counter).mount('#root', { mode: 'adopt' });

console.log('Kept the server button:', document.querySelector('#root button') === serverButton);
serverButton.click(); // the client's handler is bound to the server's node
console.log('Count after a click:', count.value);

In an app, the server writes the document with renderDocument(view, { scripts: ['/main.js'] }) and main.js mounts the same view:

// main.js
import { App } from 'swiftui-for-web';
import { Site } from './Site.js'; // the same view the server rendered

App(Site).mount('#root', { mode: 'adopt' });

Islands with whenVisible

The swiftui-for-web/islands entry exports whenVisible(host, load, { rootMargin }). It imports no framework code itself, so a page whose islands are off-screen loads no framework JavaScript until they come within rootMargin (default 200px) of the viewport. load runs once, with the host; the call returns a function that stops watching. Without IntersectionObserver it loads right away.

Static controls on the page can drive an island by writing a State that the island module exports: one app serves any number of triggers.

<script type="importmap">
  {
    "imports": {
      "swiftui-for-web": "/node_modules/swiftui-for-web/src/index.js",
      "swiftui-for-web/islands": "/node_modules/swiftui-for-web/src/islands.js"
    }
  }
</script>

<div id="finder"><p>Static fallback list…</p></div>
<button type="button" data-query="swift">Swift</button>
<button type="button" data-query="metal">Metal</button>

<script type="module">
  import { whenVisible } from 'swiftui-for-web/islands'; // loads no framework code

  whenVisible('#finder', async () => {
    const { query } = await import('./finder-island.js');
    for (const button of document.querySelectorAll('[data-query]')) {
      button.addEventListener('click', () => { query.value = button.dataset.query; });
    }
  });
</script>

// finder-island.js
import { App, VStack, Text, State } from 'swiftui-for-web';

export const query = new State('');   // the page's buttons write this

const Finder = () =>
  VStack({ alignment: 'leading', spacing: 4 },
    Text(() => (query.value ? `Results for “${query.value}”` : 'Pick a topic'))
  );

App(Finder).mount('#finder', { mode: 'replace' });

The import map points the package names at the files; adjust the paths to where the framework is served, or import the files by path (./src/index.js) as the examples in this repository do. A --bundle release build puts the island and the framework code it uses into one module.
