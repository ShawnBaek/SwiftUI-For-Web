Presentations

.sheet, .fullScreenCover, .alert and .confirmationDialog share one controller built on <dialog>.showModal().

The binding is the source of truth

Each presentation shows while its isPresented binding is true. Every way of closing it writes false to the binding: Escape, a backdrop click (except for an alert), an action, or dismiss(). onDismiss runs once, after it closes.

ModifierSignature
.sheet.sheet(isPresented, content) or .sheet(isPresented, { onDismiss, content })
.fullScreenCover.fullScreenCover(isPresented, content) or .fullScreenCover(isPresented, { onDismiss, content })
.alert.alert(title, isPresented, { actions, message, onDismiss })
.confirmationDialog.confirmationDialog(title, isPresented, { titleVisibility, actions, message, onDismiss })

Alerts and confirmation dialogs

Actions are buttons with SwiftUI roles: Button('Delete', { role: 'destructive' }, action), or plain objects { title, role, action }. Escape runs the cancel action. With no actions, one “OK” button is shown. An alert is role="alertdialog", labelled by its title and described by its message.

import { App, VStack, Text, Button, State, Color } from 'swiftui-for-web';

const showAlert = new State(false);
const confirmDelete = new State(false);
const log = new State('Nothing yet');

App(() =>
  VStack({ spacing: 12 },
    Button('Sign out', () => { showAlert.value = true; }),
    Button('Delete photo…', () => { confirmDelete.value = true; }).foregroundColor(Color.red),
    Text(() => `Last choice: ${log.value}`)
  )
    .padding(24)
    .alert('Sign out?', showAlert.binding, {
      message: 'You can sign back in at any time.',
      actions: [
        { title: 'Sign out', role: 'destructive', action: () => { log.value = 'Signed out'; } },
        { title: 'Cancel', role: 'cancel', action: () => { log.value = 'Stayed'; } },
      ],
    })
    .confirmationDialog('Delete this photo?', confirmDelete.binding, {
      titleVisibility: 'visible',
      message: 'It will be removed from all your devices.',
      actions: [
        Button('Delete', { role: 'destructive' }, () => { log.value = 'Deleted'; }),
        { title: 'Cancel', role: 'cancel' },
      ],
    })
).mount('#root');

Sheets, full-screen covers and dismiss

Presented content finds dismiss in its environment, like SwiftUI’s @Environment(\.dismiss). Calling it writes false to the binding that presented the view.

import {
  App, VStack, Text, Button, State, Environment, EnvironmentValues, Font
} from 'swiftui-for-web';

const showSettings = new State(false);
const showPlayer = new State(false);

const Settings = () => {
  const dismiss = Environment.get(EnvironmentValues.dismiss);
  return VStack({ spacing: 12 },
    Text('Settings').font(Font.title2),
    Button('Done', () => dismiss())
  ).padding(24);
};

const Player = () => {
  const dismiss = Environment.get(EnvironmentValues.dismiss);
  return VStack({ spacing: 12 },
    Text('Now playing').font(Font.largeTitle),
    Button('Close', () => dismiss())
  ).padding(40);
};

App(() =>
  VStack({ spacing: 12 },
    Button('Settings', () => { showSettings.value = true; }),
    Button('Play', () => { showPlayer.value = true; })
  )
    .padding(24)
    .sheet(showSettings.binding, { onDismiss: () => console.log('Settings closed'), content: Settings })
    .fullScreenCover(showPlayer.binding, Player)
).mount('#root');

Behaviour

  • The page behind is inert while anything is presented, focus is trapped in the presentation, and page scroll is locked.
  • Focus returns to the element that presented it.
  • Presentations stack: a sheet can present an alert, and closing the alert returns to the sheet.
  • A backdrop click dismisses a sheet, a cover or a confirmation dialog, but not an alert, as in SwiftUI.
