Accessibility

Controls render native elements where the platform has one, and follow the WAI-ARIA Authoring Practices pattern, with keyboard support, where it doesn’t.

What each control renders

ViewElement or patternKeyboard
Button, NavigationLinkNative <button>; a NavigationLink with a URL is <a href> (relative, http(s), mailto and tel URLs only).Enter, Space
ToggleSwitch style: <button role="switch" aria-checked>. Checkbox style: a native checkbox.Space
SliderNative range input.Arrows, Home, End
TextField, SecureFieldNative text and password inputs.—
PickerMenu style: native <select>. Segmented: radiogroup with a roving tabindex.Arrows in the segmented style
List with selectionlistbox of options with aria-selected and a roving tabindex; a Set selection adds aria-multiselectable.↑ ↓, Home, End, Space
TabViewTabs pattern: tablist, tab, tabpanel, in both styles.Arrows, Home, End
MenuMenu button: aria-haspopup="menu", aria-expanded, a menu of items.Arrows, Escape
DisclosureGroupDisclosure: a button with aria-expanded.Enter, Space
.sheet, .alert, …<dialog> with showModal(): the page is inert, focus is trapped and returned. An alert is alertdialog, labelled by its title and described by its message.Escape

Try the listbox: click a row, or Tab into the list and use the arrow keys and Space.

import { App, VStack, List, Text, Toggle, Picker, PickerStyle, State } from 'swiftui-for-web';

const selection = new State(new Set(['b']));
const wifi = new State(true);
const size = new State('m');

App(() =>
  VStack({ alignment: 'leading', spacing: 16 },
    Toggle('Wi-Fi', wifi.binding),
    Picker('Size', size.binding,
      Text('Small').tag('s'), Text('Medium').tag('m'), Text('Large').tag('l')
    ).pickerStyle(PickerStyle.segmented),
    List({ selection: selection.binding },
      Text('Alpha').tag('a'),
      Text('Bravo').tag('b'),
      Text('Charlie').tag('c')
    ),
    Text(() => `Selected: ${[...selection.value].join(', ') || 'none'}`)
  ).padding(24)
).mount('#root');

Accessibility modifiers

ModifierRenders
.accessibilityLabel(label)The accessible name (aria-label).
.accessibilityValue(value)The current value, read after the name.
.accessibilityHint(hint)A description of what happens on activation.
.accessibilityIdentifier(id)An identifier for tests; not announced.
Text(…).accessibilityHeading(level)A heading element, AccessibilityHeadingLevel.h1 to h6.

Label, value and hint accept a State and stay in sync.

import {
  App, VStack, HStack, Text, Button, State, AccessibilityHeadingLevel, Font
} from 'swiftui-for-web';

const volume = new State(5);
const volumeText = new State('5 of 10');
const set = (value) => {
  volume.value = Math.max(0, Math.min(10, value));
  volumeText.value = `${volume.value} of 10`;
};

App(() =>
  VStack({ alignment: 'leading', spacing: 12 },
    Text('Sound').font(Font.title2).accessibilityHeading(AccessibilityHeadingLevel.h1),
    HStack({ spacing: 8 },
      Button('−', () => set(volume.value - 1)).accessibilityLabel('Quieter'),
      Text(volume)
        .accessibilityLabel('Volume')
        .accessibilityValue(volumeText),
      Button('+', () => set(volume.value + 1))
        .accessibilityLabel('Louder')
        .accessibilityHint('Raises the volume by one step')
    )
  ).padding(24)
).mount('#root');

Focus and motion

  • The stylesheet (src/styles/reset.css) draws a 2px focus ring on :focus-visible.
  • With prefers-reduced-motion, removal transitions are immediate. A view that is animating out is aria-hidden and takes no pointer events, so assistive technology never reads a view that is already gone.
  • Presentations return focus to the element that opened them.

Known gaps

  • Stepper’s − and + buttons have no accessible names of their own.
  • The inline and wheel Picker styles have no keyboard support.
  • .disabled() is missing on Slider, Stepper, Picker, DatePicker and ColorPicker.
